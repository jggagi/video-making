# 小红书手动发布包

按 Q 于 2026-10-23 更新的分工，为已完成的视频准备可检查的本地发布材料。Q 手动上传视频、填写页面、选择话题与声明，并决定是否保存草稿、定时或提交。这个长期偏好适用于后续作品；普通的“帮我发”或旧版 Auto-Publish 请求也只生成发布包和手动交接。只有 Q 明确改变这项长期偏好时，才重新评估工作边界。

遇到“直接发”“填标题保存草稿”等普通续接请求时，提供可复制文案和本地发布包，说明对应平台步骤由 Q 手动完成；不为恢复代发另开确认流程。

## 本地发布包

只处理当前作品，不要求为了发布包重做视频。读取本地成片和已有验收记录，核对目标版本，并记录能实际验证的文件路径、字节数、SHA-256 和时长。缺少证据时保留未知状态；文件存在或静态截图都不能代替音视频完整性检查。

整理与成片对应的封面和文案材料：

- 记录最终封面路径及散列；保留原始来源路径、来源帧或素材、裁切坐标和输出信息。
- 提供选定短标题草稿及原始标题，保留用户指定正文；科学示意不得写成实测成果。
- 提供话题草稿和内容声明建议。话题草稿不是已关联的话题，声明建议也不是页面上已作出的选择。
- 附上适合手动操作的短清单，以及实际完成的本地 QA 状态。自动检查不能冒充人工听看；未完成的人工视觉或音频检查保持未完成。

优先延续作品 `小红书/` 下已有材料；没有既有格式时，用 `publication-copy.md` 保存标题、正文和话题草稿，`publication-package.json` 保存文件身份与状态，`manual-publish.md` 保存用户操作说明。已有 SRT 一并交付，成片与封面保持原路径，不为凑发布包复制一套大文件。

新建记录可从[发布记录模板](assets/publication-record-template.json)开始。准备与核验完成后可设置 `prepared: true`、`status: READY_FOR_MANUAL_PUBLICATION`，提交相关状态仍按实际证据填写。新作品明确尚未提交时 `submission_attempted: false`；既有记录结果不明时保留 `null`，不覆盖历史。记录只存与本次作品有关的信息；不要为了准备材料读取账号或管理页。

## 用户手动交接

交付时明确指出视频、封面、标题、正文、话题草稿、声明建议和记录文件的位置，并说明本地核验与人工 QA 的真实状态。由用户在小红书界面手动：

1. 上传选定视频并检查平台处理后的预览。
2. 添加封面，填写标题和正文。
3. 从页面中选择并确认实际关联的话题。
4. 根据当前内容和页面选项选择 AI 内容声明。
5. 检查可见范围与发布时间，再由用户决定保存草稿、定时或提交。

这些步骤是给用户的交接清单。Codex 不登录账号、不上传、不填写或修改编辑器字段、不保存草稿、不安排发布、不最终提交，也不通过 API、ADB、浏览器自动化或其他通道写入账号。用户完成后可自行更新记录，或提供信息供 Codex 记录；未发生的动作不得标作已完成。

## 只读状态核验

仅当用户明确要求检查既有作品或账号状态时，才进行可用的只读核验。准备本地发布包时不读取账号、不搜索旧笔记。用户提供的状态与平台实际页面观察分开记录；只报告看见或收到的证据，不推断提交成功、审核状态或公开可见性。

只读核验可复用用户已有登录态，或读取用户提供的笔记链接、截图；需要重新登录时由用户自行完成。结合账号、标题、时长、封面与笔记 ID/链接匹配目标。本地文件散列不代表平台验证过相同散列。管理页的“审核中”“已发布”与公开笔记页的实际可访问性分别记录；登录态编辑预览不能证明对所有人公开。页面时间保留原文，检查时间优先记 UTC，不自行推断未知时区。待审核时报告当前结果后结束，不自动轮询或建立后台任务。

使用[EP04 历史个案](references/ep04-submission-case.md)时，只把它当作当时发生过的事实记录；旧工作流不再生效。

## 记录与证据边界

保留草稿值、用户报告和平台观察之间的区别：

- draft_topics 和 draft_content_declaration 是建议材料；linked_topics、content_declaration 只有在用户动作发生后且有相应记录时才填实际值。
- planned_publisher 可标为 user；final_action_actor 在实际动作发生并有证据前保持空值。
- upload_status 与 upload_status_source 只记录已有上传的实际证据，来源区分 user_report 与 platform_observation；本地包准备完成不等于已上传。
- submission_attempted 仅在有提交操作证据时填写；未知时保留 null。submission_verified、publication_verified 和 public_visibility_verified 仅在各自证据成立时标为 true。
- 三个 verified 字段为 false 表示尚未取得对应确认，不表示“已检查并证实没有提交/发布”；实际页面结果另记 platform_observed_status。
- 标记状态来源为用户报告或平台观察。最终按钮点击或口头反馈不等于平台确认；审核中、定时、提交未知和公开可见是不同状态。

二维码、Cookie、验证码、会话标识和未脱敏的账号页面截图只留在私有位置，不进入公开 Git、Release 或发布包。私有证据路径也只记在本地私有记录，公开材料仅保留必要的脱敏结论。交付说明只陈述已完成的本地工作、剩余人工检查和用户的下一步。原工程已有的 GitHub 源码、作品 Release 与 final 备份归档继续按原授权执行。
