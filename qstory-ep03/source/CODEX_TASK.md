# EP.03 Remotion执行任务

为“余问 QStory｜感受SI”制作《十万亿个分身》的Remotion预览项目。以本目录EP03_director_brief.md、EP03_timeline.json和EP03_narration_zh.txt为唯一片内文案与时间轴基线。

这是一个具体短片工程，不是新产品平台。用户当前正式开发主机是Mac mini；在现有工程中先检查文件，保留用户修改。没有现有工程时才新建独立qstory-ep03目录。不要覆盖任何其他项目。

## 先加载Skill

先加载本机已安装的Remotion官方skill。未安装时使用官方命令：

```bash
npx skills add remotion-dev/skills
```

新工程的官方空白模板入口：

```bash
npx create-video --yes --blank qstory-ep03
```

只在工程不存在时运行创建命令。核对package.json与lockfile，将remotion及@remotion/*保持兼容且版本一致，不盲目升级现有项目。依照已安装的remotion-best-practices读取create、markup、captions等适用参考；API有疑问时用对应版本官方文档核对。不要声称仅阅读了说明就等于调用了视频生成工具。

## 创作硬约束

1. 180秒、30fps、5400帧；横版1920×1080为先，竖版1080×1920重新布局。
2. 悬念以未说完的一句话开场，最终回到同一人声。没有昂贵外部素材也能完成第一版。
3. 高潮是110—145秒的反例传播，必须有“发现→送达→复核→撤回/修改→保存证据”。不要把异议烧掉后宣布全体一致。
4. 《十万亿个分身》不作实例数量实测。主片不显示“全球同步零延迟”“1ms完成全部科学研究”。
5. 画面不是大字PPT，不用机器人头像墙，不堆仪表盘，不把共识当作正确性。
6. 全部动画可逐帧确定性求值，节点ID与seed稳定。用稀疏依赖图，批量绘制大规模点。
7. 场景总时间以JSON为准；不要因转场重叠改变总长。已在时间容器中获得局部帧后，不可再重复偏移。
8. 当前SRT是计划字幕，不是真实录音的强制对齐结果。无音频时明确标“无声预演”；不得编造不存在的素材路径。
9. 不进行真实Agent运行、模型API调用、实时科学模拟或用户数据云上传；所有视觉事件由本地预编排数据驱动。
10. 不分发系统字体，不使用来历不明音乐或既有科幻电影画面。

## 实现顺序

A. 检查工程与依赖；建立最小可运行预览并打开Studio。
B. 先做110—145秒高潮的可读灰模，围绕同一个C-17证据对象。
C. 按24镜头与8场景补全180秒低细节预览；字幕与人声占位明确。
D. 加入真实音频并重对齐字幕，核对129—130秒静音；再完成材质、光效、镜头和竖版。
E. 运行本包validate.py检查元数据；另做TypeScript检查、Studio预览与关键帧视觉检查。各类检查分别记录，不相互替代。

先交付可预览工程及真实测试结果。没有明确导出要求，不自动长时间导出所有平台版本；需要导出时使用官方render入口，并检查最后一帧和最终音画。
