# 声音、双画幅与验收

在配音、混音、完整渲染和最终验收时按需要读取。这里补充自动媒体检查没有覆盖的真实制作问题。

## 一条时间轴，两种布局

- 目标时长为 `T = delivery.json.duration_seconds`，项目规格先写入清单；缺省为 120 秒。`T > 0`，`T × fps` 与 `T × 48,000` 必须为整数。两版 Composition 的 `durationInFrames = T × fps`、字幕结束边界、PCM 母带样本数和时间轴上限全部锁定同一个 `T`，片头片尾计入其中。
- 默认 60 fps / 48 kHz：120 秒为 7,200 帧、每声道 5,760,000 个 PCM 样本；180 秒为 10,800 帧、每声道 8,640,000 个样本。变更 `T` 时同步更新清单、Composition、字幕和母带，不能只改导出文件名。
- 默认原生画布为横屏 3840 × 2160、竖屏 2160 × 3840，两版均为 4K。1080 × 1920 是明确请求的轻量版或旧清单规格，不是新作默认值；不能用放大已编码视频充当 4K。
- 画面布局不控制叙事时间；全局时钟、计数、事件和声音由共享时间轴产生。一个关键事件在横屏和竖屏应发生在同一帧。
- 竖屏可以把同时出现的多个标签改为顺序出现，保持意义和对应旁白一致。字体、主物与字幕的尺寸基于真实手机观看，而不是桌面放大图。
- 先分别看静帧和短样片。检查代表帧之外的运动问题时，选择覆盖完整转场的短片；单帧清晰不能证明运动中无闪烁或拖影。

## 素材与生成复用

- 同一作品只维护一份剧本改编、分镜、素材清单、配音段落和共享 PCM 母带。图片/视频、字体、音乐/音效放在共同工程素材目录，横竖屏通过相同资源 ID 和文件路径引用；平台目录保存对应成片、字幕和发布附件，不重复存放同一源素材。
- `project/assets-manifest.json` 记录资源 ID、路径、SHA-256、生成文本/提示词、提供商/模型/参数及缓存标识。图片/视频生成键包括内容、模型、尺寸与生成参数；TTS 键包括 `tts_phonetic_text`、提供商、模型、声音、语速和采样参数，不能仅按平台名另建同内容生成任务。
- 改画幅只改布局。先查缓存，缺失或内容变化时才生成对应资源；单一资源局部重试，不重跑整片素材或全部配音。新构图/清晰度确需变体时记录原因并复用其余资源。后续步骤传递清单、资源 ID 和增量修改，避免反复展开完整提示词和剧本。这样减少重复 token、TTS 与图像/视频生成调用；本地两版 4K 渲染仍分别执行。

## 配音与混音

- 剧本文字、显示字幕、`tts_phonetic_text` 分别保留。TTS 输入必须显式展开数学符号、科学记数与单位，例如 `7±2` → `七加减二`、`10^5` → `十的五次方`、`TB/s` → `每秒太字节`。连续中文数量词必须用标点分隔或经提供商验证的读音提示消歧，例如 `十万亿个分身` → `十万亿，个分身`，重点防止 `亿（yì）` 弱化误读为 `一（yī）`。先试听这些词再批量生成；标点不是发音正确的证据。保持显示文本与原意，不得把改写后的文本伪装成原文逐字朗读。
- 缓存清单保留段落 ID、文本、提供商/模型/声音/语速、文件相对路径、SHA-256、采样率、声道与实际样本数。相同文本但声音或设置不同，不复用为同一缓存。
- 每段先验真实格式并严格解码。遇到 WAV 头宣称的 RIFF/data 长度超过实际数据时，先保留提供商原始文件；只有在确认 PCM 参数、字节对齐和实际载荷后才另存修复版，并保存载荷哈希和修复说明。不要单凭扩展名信任格式。
- 以原始 PCM 样本数和采样率计算时长，母带每声道恰为 `T × 48,000` 个样本。字幕可以使用句段对齐；没有逐字证据时不能声称逐字同步。
- 长台词装不进镜头时，先调整改编稿与镜头分配。禁止默认用整轨加速、截尾或静默删掉必留句子来满足时长。
- 两版使用同一 PCM 母带，保留独立旁白、配乐、程序化音效与混音设置。节点过载/断裂、MCTS 分支剪除、流形锁定等关键相变必须从共享视觉时间轴导出准确事件帧（如 `project/sfx-events.json` 的事件 ID、帧号与样本位置）。音效起点由 `sampleIndex = frame × sampleRate / fps` 计算，不能凭秒数手调；非整样本映射须记录取整误差。当前支持的整数帧率在 48 kHz 下均可精确映射。
- 瞬态音效与旁白重叠时，将旁白起音错开 150–300 ms，或对音效削减 1–4 kHz 人声频段；调整后重新检查字幕和 `T` 边界。母线必须使用具备真峰值控制的砖墙限制器，使单帧触发的瞬态也不超过 −1 dBTP；补偿限制器延迟，保留准确事件起点和母带样本数。AAC 编码后重新测量，若编码过冲则降低限幅上限再导出。
- 检查转场突变、噪声/静音设计边界及尾音；配乐避开旁白频段和音量竞争。约 −18 至 −16 LUFS 是可按内容调整的混音起点，−1 dBTP 是本流程的真峰值上限；这些是制作选择，不是声称平台强制规范。
- 真峰值和 LUFS 需真实测量，例如对最终文件执行 `ffmpeg -i <视频> -af ebur128=peak=true -f null -`。PCM 样本峰值不能代替真峰值；测得合格也不能代替听音。
- 可用本地解码结果与 PCM 母带的同时间窗口做相关性/波形检查，分别覆盖开场、中段关键事件和结尾。AAC 是有损编码，不要求解码样本逐字节相同；比较前处理并记录采样率、通道和时间偏移。
- ASR 属于可选的发音核对手段。上传到云端须处于已有授权范围；数字、同音字、语气词差异保留供复核，不能清洗差异后宣称原字无误。

## 竖屏安全区与最小字号

- 9:16 关键节点、HUD 遥测与字幕避开顶部 8%、右侧 14%、底部 22%，即核心区域的上边界为 `0.08H`、右边界为 `0.86W`、下边界为 `0.78H`。整块文字/节点包围盒都须满足边界，不能只检查中心点。
- 字幕锚点处于距底部 24%–28% 的阅读带，即距顶部 `0.72H–0.76H`；检查多行包围盒仍在安全区内。不要把它误读为画面顶部 24%–28%。按具体 App 和真机反馈增加余量。
- 在 360 px 宽手机预览中，字幕/正文有效字号至少 13 px，核心遥测标签至少 10 px。1080 px 宽原生画布至少对应 39 / 30 px，2160 px 宽至少对应 78 / 60 px；还需计入嵌套缩放、透视和最终下采样。长句分段、重排，不能靠缩字塞入。

## 完整渲染前的文字与运动门槛

- 静态核对全部英文 HUD/遥测常量和字幕数组，保留术语表，重点检查 `CAUSAL`（不要写成 `CASUAL DEPTH`）、`MANIFOLD`、`TELEMETRY`。运行 `python3 <本技能目录>/scripts/validate_delivery.py <作品目录> --source-only`；它扫描 `.tsx/.ts/.json` 常见误拼，不自动改写，也不能替代全量术语/字幕校对。该调用的顶层状态始终是 `INCOMPLETE`（未检查媒体）；只看 `source_scan.status` 判断源码扫描，空扫描也不算通过。
- **3 秒运动规则**：包括标题卡、章节转场和全屏矩阵在内，任何镜头不得连续空间静止或仅原地闪烁超过 `3 × fps` 帧（60 fps 时为 180 帧）。长停留必须持续演进，如 `rotateX/Y` 透视倾转、Z 轴相机飞行、背景线框旋转；数字跳动、透明度脉冲或噪点闪烁不能单独满足要求。构图中对象锁定时仍保留相机或环境的空间运动。
- 镜头表标出所有超过 5 秒的停留及其持续运动来源。工程帧检查覆盖停留内部与转场两侧；单个首尾变化不能证明中间没有超过 3 秒的冻结。

## 体验类影片的观看检查

适用于“感受 SI”及明确以感受或直觉为目标的影片，先按 [体验叙事参考](experience-led-storytelling.md) 在 brief 和分镜中写明目的。教程、数据分析和推导保留其所需的信息深度。

完整渲染前，用带真实旁白和声音的代表片段检查主体动作、后果与情绪转折；片段应体现全片的观看方式，不能只检查结尾。按正常速度和目标尺寸连续看一遍，记录留下的画面、感受、核心直觉，及需要暂停、重读或同时追踪多处细节的位置。若观众主要在阅读注释，回到分镜，减少非必要说明并让动作承担因果；必要的科学限定仍留在可见位置。

在 `review/acceptance.md` 分开记录创作者自评、模型辅助观察和实际观众反馈。没有真实观众反馈时如实保留待确认，不新增默认审批或等待环节；模型描述的情绪不能填成普通观众的实际感受。此项补充内容准确性与下列技术检查。

## 技术验收的边界

正式新作另执行 [防闪烁与逐帧验收](visual-integrity.md)：对每版最终 MP4 从起点连续筛查全部帧，记录检测范围和文件哈希，复核每个异常及其邻帧。严格解码与稀疏抽帧会漏过合法码流中的偶发重复画面块；短样片只能验证样片覆盖的部分。检测结果不等于全画面感知或人工连续听看通过。

`validate_delivery.py` 按清单中的 `T` 检查媒体文件，缺省 120 秒。原有 CLI 保持可用，`--scan-source` 可在完整媒体检查中追加拼写扫描。它不分析内容是否忠实、中文是否清晰、音轨是否来自共同母带，也不验证 LUFS、发音、连续空间运动、暗部色带或真实 App 播放。完整交付需结合工程检查与下列证据。

| 层次 | 保留的证据 | 不能据此声称 |
| --- | --- | --- |
| 工程 | 类型检查、总帧数、字幕无越界、素材/依赖锁定与固定种子 | 视频已经正确导出 |
| 实际媒体 | FFprobe 实测、严格全片音视频解码、fast start、SHA-256 | 内容、观感与听感已获用户认可 |
| 模型代表帧检查 | 来自实际 MP4 的带时间码抽帧/总览及观察记录 | 连续观看、无运动瑕疵或人工试听通过 |
| 声音测量 | LUFS/真峰值、音轨长度、同步窗口、母带比对 | 发音和情绪表达正确 |
| 人工/设备 | 用户明确的完整观看/听音与实际手机/显示器播放反馈 | 未检查的平台压缩、账号上传或长期可用性 |

逐版检查的画面至少覆盖：开头、各叙事转折、最快/最复杂的运动段、最长字幕、核心台词、主要事件前后和最后一帧。对竖屏制作约 360 px 宽总览并查看关键截图；大屏查看 4K 字体、细线和素材清晰度。把实际观察写进 `review/acceptance.md`，不要只写“已检查”。

### 成对帧与暗部渐变

对每个超过 5 秒的镜头/标题卡，从最终编码 MP4 抽取同一镜头内相隔 2–3 秒的成对帧，例如 `t` 与 `t + 2.5s`。长镜头取多组覆盖停留内部；观察几何形状、透视或空间位置的推进，不把计数器、字幕切换或亮度闪烁当作运动。保留时间码、帧图和观察结果。

可选的轻量结构差分：下面以 12 与 14.5 秒为例，先裁掉 HUD/字幕再比较边缘差值。**按该镜头的真实布局调整 ROI，确保排除全部计数器和字幕**；示例裁切不是通用 HUD 遮罩。

```sh
ffmpeg -ss 12 -i <最终MP4> -ss 14.5 -i <最终MP4> \
  -filter_complex '[0:v]crop=iw*0.72:ih*0.50:iw*0.07:ih*0.20,scale=160:90,format=gray,edgedetect[a];[1:v]crop=iw*0.72:ih*0.50:iw*0.07:ih*0.20,scale=160:90,format=gray,edgedetect[b];[a][b]blend=all_mode=difference,signalstats,metadata=print:key=lavfi.signalstats.YAVG' \
  -frames:v 1 -f null -
```

`YAVG` 接近零（例如 0–255 标度下低于 0.5）时警告疑似冻结，回看成对帧和连续片段；阈值是启发式，不是通过标准。稀疏/低对比运动可能误报，闪烁或漏掉的 HUD 可能掩盖冻结。差分非零也不能替代 3 秒运动规则的人工核对。

对 4K `bt709` / `yuv420p` 导出，另抽径向光晕、渐隐和 `#050811` 等暗色背景的实际 MP4 帧，在各版原生 4K 尺寸（3840 × 2160 或 2160 × 3840）大屏检查严重色带/等高线。记录 FFprobe 的像素格式与色彩标记，不能仅凭渲染参数认定编码正确；缩小总览不能作为暗部验收。发现色带时检查渐变量化、码率/编码质量和必要的细微抖动，再从最终编码重新抽帧复核。

MP4 的 AAC 尾部可能比视频轨长约 11 ms。视频仍必须精确达到 `T × fps` 帧与 `T` 秒；分别记录视频、音频、容器时长。若偏差超过 50 ms，检查编解码填充、起止点和复用的母带，不能把真实多余内容归为填充。

归档保留可编辑源码、剧本原稿和改编稿、字体/素材与来源、锁文件、时间轴、本地配音与音轨母带、生成设置及精简 QA。不要携带凭据、node_modules、缓存 bundle 或无关旧电影。打 ZIP 时核对 CRC 和逐文件哈希；最终 MP4 仍放在各平台目录，避免只藏在源码包里。
