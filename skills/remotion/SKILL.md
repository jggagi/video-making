# Remotion

把内容与传播目的转化为可观看、可修改、可复现的视频。先让每个镜头清楚表达信息，再用素材、声音和运动组织注意力与节奏。

## 接手任务

- 先读现有工程、入口、Composition、脚本、锁文件和素材，沿用已选工具链、提供商与有效资产。局部修改限定到相关组件或镜头，另存新版成片。
- 从会话中提取内容、受众、播放场景、画幅、时长、声音、风格与交付要求。只补问影响制作的缺失信息；其余说明合理假设后推进。
- 区分新建、改进已有影片和单个镜头修正。用户只改画面时，尽量复用既有音频与时间轴；不用每次重做整套制作。
- 以用户选择为准。水墨、AI 图片、旁白、男声、4K、展厅和全文朗读均是可选方案。

## 内容与视觉设计

建立可核对的内容依据：脚本、原文、数据、产品状态或用户素材。保留关键事实、数字、顺序与因果；演示画面应区分真实功能和概念方案。为镜头记录内容依据、观看者需要理解的要点、视觉动作、素材和时长依据，粒度随任务调整。

先确认传播目的是体验、直觉还是深入理解。Q 的“感受 SI”系列及明确的体验类任务，先定希望留下的画面、感受与核心直觉，再用主体动作、可见后果、尺度、节奏和声音组织分镜；理论约束因果，必要限定保留可见。具体方法见 [视觉设计与素材](references/narrative-and-art.md) 的“体验优先的分镜”。教程与数据讲解仍按用户要求保留深度。

选择适合内容的表现形式：文字、SVG、图表、代码绘制图形适合精确且可编辑的表达；截图或实录适合产品操作；照片、插画或生成素材适合场景与叙事。先看代表静帧，确定构图、字体、色彩、主体尺度与阅读留白，再扩展和加动画。品牌、数字、字幕和关键 UI 文字优先用可控排版。

分镜、素材与镜头衔接见 [视觉设计与素材](references/narrative-and-art.md)。插画叙事或伏笔容易漏看时，使用其中的线索与静态镜头检查。诗词、古文或其他文学文本需忠实转译时，另读 [文学短片](references/literary-film.md)，其中链接《兰亭集序》案例。

## 时间与声音

有录音时，以实际音频时长建立镜头与字幕；没有旁白时，用阅读、信息变化和动作所需时间确定节奏。把场景、字幕和音频的起始帧、持续帧组织在可检查的数据中，计入留白与转场。检查总时长、片尾完成状态与相邻镜头衔接。

需要 TTS 时，尊重已选提供商、模型、音色、预算与输入授权；先验证短样本，再按可独立修改的段落生成并缓存。字幕内容与发音控制分开保存。选型时核对当前官方能力与价格，不把案例模型当作长期默认。配音、缓存、混音和展厅声音见 [声音、时间轴与交付](references/audio-and-delivery.md)。

## Remotion 实现

- 先确认项目安装的版本与现有实现方式，再选择可用 API。需要查版本能力时读本地包或当前官方文档；不要顺手升级工程。
- 用帧数驱动所有运动与状态，通常通过 `useCurrentFrame` / `useVideoConfig` 取得时序。使用固定种子的随机序列（如需要），避免实时计时、非固定随机数或实时网络数据造成预览与导出不一致。
- 从项目约定的逻辑画布安排位置与比例，复用必要的场景、排版和字幕组件。用项目支持的媒体组件加载资源；检查字体、素材和异步数据在渲染时已就绪。
- Canvas/DOM 混合捕获须等待每帧绘制和字体就绪后再释放渲染；固定延时与单纯降低并发不能证明同步正确。记录实际 Remotion/Chrome 版本、原生尺寸、中间帧格式和并发；切换捕获配置后重验原生短片，再核对最终全片。GPU 设置按渲染器和实测选择，不对 WebGL 或其他机器全局禁用。
- 每个动作承担明确用途：引导视线、解释变化、展示操作、形成情绪或连接镜头。让文字有足够阅读时间；推拉、位移、图表变化和转场不应破坏主体、坐标或阅读。
- 对分层图片保持坐标、尺度和遮罩一致，避免重复叠层变暗。为不同状态复查字幕与前景遮挡。精确素材编辑先查看原图，独立运动素材需要时使用真实透明背景。
- 先渲染受影响的静帧与短片段，覆盖动作极值、转场中点和完成状态；确认后再导出全片。复杂任务可按当前环境规定分工，任务边界写清目标、文件、保留条件和可观察的验收标准，主代理负责整合与最终验证。

## 验收与交付

按本次修改和用途选择检查：内容与时间轴核对、适当的代码检查、真实渲染静帧与片段查看、最终文件规格和完整解码、最终视频抽帧。数据动画核对数值、单位与比例；产品演示核对操作与状态；叙事片核对画面与内容关系。不要用代码检查代替画面验收。

在 `video-making` 仓库制作正式新片时，保留 `delivery.json` 的必需视觉验收策略，按 [防闪烁与逐帧验收](../dual-platform-video/references/visual-integrity.md) 连续检查两版最终编码的全部帧，复核异常并绑定文件哈希。文件可解码、短样片正常和稀疏抽帧均不能证明全片无偶发坏帧；任何修补或重编码后重新检查对应最终文件。其他项目按实际规模选用此方法，记录未覆盖范围。

体验类影片在完整渲染前，用带真实旁白与声音的代表片段检查正常速度下的感受、动作因果与阅读负担，覆盖主要观看方式和转折。技术检查通过不能代填体验有效；分别记录创作者自评、模型辅助观察与实际观众反馈，未做的观众验收保持未执行。

播放器属于本次交付或受修改影响时，验证实际播放和跳转。画幅、编码、声音、字幕、观看距离和循环按播放设备要求处理。区分自动校验、人工听看与现场试播；只报告实际完成的证据。输出分辨率与素材原始分辨率分别说明，生成图片或合成声音如实标明。

交付可用成片与可编辑工程，以及任务所需的字幕、音频、素材来源和简洁验证记录。直接展示成片或改动片段，链接完整文件；版本保留遵循现有项目约定，避免覆盖已认可结果。具体媒体验收与展厅模式见 [声音、时间轴与交付](references/audio-and-delivery.md)。

需要形成可交接验收记录时，可复制 [影片验收模板](assets/film-acceptance-template.md)，按任务保留适用项，分别记录技术检查、实际播放、听看评审和必要的重建验证。

在 `jggagi/video-making` 仓库生成或修订正式成片时，完成该仓库约定的本地 `final/<作品版本>/<平台>/` 留存和GitHub专用 `final-*` Release 实际影片备份；保留原工程路径与旧版本，核对大小和SHA-256，并抽测新增影片恢复。执行步骤见同一技能集合中的 [仓库归档约定](../dual-platform-video/references/github-archive.md)。其他项目遵循自身交付约定。
