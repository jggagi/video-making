# 小红书视频发布

接收已完成的视频，通过当前可用且获准的浏览器或应用工具完成发布，并留下可续接的记录。视频可以来自任意工程；不要求先重做视频或满足本仓库的默认制作规格。

## 接手与授权

先区分本次要准备材料、上传草稿、正式发布，还是只核验某次状态，按对应阶段接手。仅查询状态时直接读已有记录与管理页，不要求重新准备本地媒体、封面或文案，也不执行上传和提交。

先提取本次作品版本、视频路径、目标账号、标题正文、封面、话题、内容声明、可见范围和发布时间。已有会话选择与素材优先复用；缺少文案时可依据成片拟写简洁草稿，不能把科学示意写成实测成果，或沿用上一集的标题与结论。只补问会影响发布对象、内容或时间的真实歧义，不重复收集已知信息。

“帮我发布到小红书”等明确请求，授权本次目标作品的上传与最终发布；完成准备后可直接执行支持的最终操作，不默认再索取一次批准。只要求制作、写文案、预览或保存草稿时，按其范围执行。创建本技能、归档到 GitHub、登录成功、历史作品的授权，均不扩展为未来作品的发布授权。

## 成片与发布材料

- 读取当前作品的媒体和验收记录，核对选中的是所需平台、版本和正式成片，记录本地路径、大小、SHA-256 与实测时长。已有有效证据可复用；缺失时做必要的媒体检查。不能把文件存在或画面截图当成音视频完整性证明，也不把待人工听看的状态改成已通过。
- 先读已有发布记录，并在获准账号的管理页查找可能已提交的同一作品，避免重发；版本散列用于本地身份，管理页匹配结合标题、时间、时长、封面及可见笔记 ID。不能声称平台已验证本地散列或转码文件相同。
- 整理标题、正文、话题与封面。保留用户指定文案；话题需要在编辑器中选择关联项，并核对已形成的话题，不能仅凭正文里出现 `#` 判定关联成功。标题、大小、时长和话题数量等限制以本次页面反馈为准，不固化某次发布的数值。
- 封面可复用用户素材或从本次成片提取清晰帧，保留来源与必要的裁切信息。在实际封面预览里检查主体、文字与裁切；旧片的帧号、3:4 裁切或封面构图不作为新片默认值。不为改封面重生成整片。

## 登录、上传与编辑

优先复用用户指定浏览器和已有授权会话，按当前工具文档选择会话、上传文件和观察页面。网页创作入口可从 `https://creator.xiaohongshu.com/` 开始；页面路径、组件、选择器和可用能力须从本次可见状态重新确认。不要为登录另建云端浏览器或导出、搬运 Cookie。

登录失效时展示当前页面中的扫码入口，让用户用自己的小红书 App 扫码并完成手机确认；需要验证码或其他身份验证时交给用户。仅在确实需要用户动作时请求协助，完成后重新读取页面和账号标识；不能凭用户说“登录了”就假定目标账号正确。多个账号或账号与预期不符时先解决歧义，再上传。

使用工具支持的文件上传能力选择准确成片，等到上传及平台处理达到可编辑、可提交状态。检查视频时长、封面和预览是否对应本次作品，之后填写标题正文、关联话题、封面、可见范围与时间选项，并逐项回读。已有明确设置优先；“现在发布”不应被改为定时，保存草稿不能被改为公开发布。

按实际制作方式和当前页面选项设置内容声明；含 AI 生成画面、合成语音等内容时如实选择相应声明，不把历史选项名称当作永久规则。不添加未经要求的定位、人物标签、商业合作或账号互动操作。

## 最终提交与工具边界

在提交前，将本次最终文件身份、账号、文案、话题、封面、声明、可见范围和时间写入发布记录，并核对页面实际值。只在上传处理完成、页面允许提交且本次发布已获授权时执行最终操作。

若最终按钮可由当前工具正常操作，直接完成。若控件不受支持、手机验证必需，或宿主明确拒绝该动作，保留已完成的准备，向用户说明具体限制和所需的最小动作，再由用户完成。不能为绕过拒绝切换低层通道、注入页面内部接口、导出凭据或盲试坐标。用户协助是条件分支，不能固化为每次都要手动点发布。

点击或请用户点击后，继续核验结果；按钮点击、跳转成功或用户反馈只是动作证据。用户说“已点击”后先读管理页，不再次点击。具体历史边界见 [EP04 提交案例](references/ep04-submission-case.md)，它不代表本次工具或页面一定相同。

## 核验、续接与停止条件

通过创作者管理页、明确结果提示及必要的笔记页面，记录实际观察到的状态。若通用“发布成功”提示与管理页的审核中、定时等状态不一致，按可对应到该笔记的具体状态记录，不能据此声称即时公开。将以下结论分开：

| 观察结果 | 可报告的结论 |
| --- | --- |
| 仅上传和编辑完成，未执行提交 | 已准备／草稿，尚未提交 |
| 最终操作已执行，管理页或结果仍不明确 | 提交结果未知，先核验，不能盲重发 |
| 管理页有匹配笔记，显示“审核中”等 | 已提交，等待平台审核；公开可见性未确认 |
| 页面显示已定时及明确的发布时间 | 已安排定时发布，尚不能报告即时公开 |
| 管理页或笔记详情明确标为已发布，且无相反的审核或定时状态 | 平台侧发布已确认；公开可见性另记 |
| 公开笔记页面实际可访问并匹配内容 | 记录链接、观察时间和访问环境；登录态预览不证明对所有人公开 |
| 页面明确显示审核失败或限制 | 原样记录原因；不自行删帖、改写再发或改账号重试 |

上传失败、登录过期和字段校验错误按实际环节修复，不从头重跑。最终操作后超时或会话中断，先查本地记录和管理页；有限次刷新或查询仍无法确定时，保留“结果未知”并停止提交，避免重复笔记。若发现重复或已有旧版本，先说明现状；不擅自删除、覆盖或重新发布。新提交应有明确的失败证据或对现有状态的确认，不能把“没看到成功提示”当作失败。

审核等待是平台状态，报告后结束本次工作；用户要求追踪时才设置后续检查或自动化，不能默默轮询、创建提醒或承诺稍后通知。

## 留存与交付

优先延续工程已有记录；没有时可用 [发布记录模板](assets/publication-record-template.json)，只保留适用字段，不要求改造已有清单。记录输入文件和散列、文案与封面来源、最终设置、执行者、提交尝试时间、观察状态、核验时间、笔记 ID/链接、证据位置、限制和剩余事项。续接时保留历史尝试和核验记录，不将旧观察改写成新证据。未知值保留空值；`submission_verified`、`publication_verified`、`public_visibility_verified` 分别表示已取得对应证据，不能互相代填。

`attempt_started_at_utc` 记录开始调用最终操作的时间。`submission_attempted` 只表示操作是否已发向平台：有执行证据时为 `true`，宿主在发送前明确拒绝时为 `false`，超时等情况无法判断是否发送时为 `null`，并将结果记为未知。`true` 不代表提交成功；`null` 不能当作未提交而直接重试。

时间戳优先记 UTC；页面显示时间另存原文，未注明时区时不自行推断。QR 码、Cookie、验证码、会话标识及未脱敏的账号管理截图保存在私有位置，不进入公开 Git/Release。可归档不含凭据和私人页面信息的精简文字记录；不擅自同步与本次作品无关的账号内容。

交付说明已完成的动作、当前观察状态、可用链接及唯一的下一步。审核中应说“已提交，审核中”，不能写成“已公开发布”。若依赖用户最终点击或有工具拒绝，说明实际分工和限制；本次只更新技能时不操作账号。
